## Gotchas while recording

- Public distribution: the source repositories are private, so the viewer only has Docker Hub images and the two downloaded files. The compose file pins `keaz/flux-gate-backend:v1.2.0`, `keaz/flux-gate-ui:v1.2.0` and (edge profile) `keaz/flux-gate-edge:v1.2.0`; there is no build option. Never `cd` into a source checkout on camera; record from an empty folder holding only the two files. The website text that links the two downloads is a placeholder until the docs page exists.
- v1.2.0 contains the first-admin fix: right after "Create Admin" the next sign-in works on every backend worker, with no restart. Earlier images returned 401 from other workers until a restart. Do not record with a `latest` image pulled before the v1.2.0 publish; run `docker compose -f docker-compose.demo.yml pull` first and check `docker compose -f docker-compose.demo.yml images` shows `v1.2.0`.
- Secrets typed or generated on screen are `<redacted>`: blur the output of `openssl rand -base64 32`, the `FLUXGATE_ENCRYPTION_KEY` and `TYPESAFE_API_KEY` values, and the admin password fields.
- Demo compose: `docs/demo-videos/assets/docker-compose.demo.yml` runs postgres, backend and ui; the `edge` service is behind profile `edge` and is started in video 08. It passes `FLUXGATE_ENCRYPTION_KEY` (required, compose refuses to start without it) and optional `TYPESAFE_API_KEY` from the host environment. `EDGE_CLIENT_ID` and `EDGE_CLIENT_SECRET` default to empty: `docker compose config` (checked, without pulling) failed on a plain `up -d` when they were marked required, because compose interpolates variables of services in inactive profiles too. The root `docker-compose.yml` of the product repository has no edge service and does not pass the encryption key, which is why the demo file exists.
- UI to backend address: the UI container has no proxy. The browser calls `${BACKEND_PROTOCOL}://${BACKEND_HOST}:${BACKEND_PORT}/api/v1` directly (`feature-toggle-ui/docker-entrypoint.sh:14-15`, also the WebSocket URL), so `BACKEND_HOST` in the compose file is `localhost`, the name the browser uses, and not the service name `backend`. Backend port 8080 is published to the host for that reason. If you record on a remote host, change `BACKEND_HOST` and `allowed_origin` in `config.demo.toml` together.
- Config path: the demo stack mounts `config.demo.toml` (same keys as the backend `config.toml`: `allowed_origin` set to `http://localhost:3000`, `http_addr`, `grpc_addr`, `public_base_url` commented out) from the folder the compose file is in.
- Deviation from the brief: the brief says `public_base_url` matters for the Jira Events URL. In the code the UI builds the Events URL from its own REST base URL (`feature-toggle-ui/src/utils/jiraIntegrations.ts:11-17`); `public_base_url` drives SSO callbacks (see `config.toml` comments). The voiceover therefore says Jira needs a public address to reach the backend, not that `public_base_url` sets the Events URL.
- Swagger path: the route is `/docs/{_:.*}` (`feature-toggle-backend/src/rest/mod.rs:769`) and the Swagger crate adds no redirect, so type the trailing slash: `http://localhost:8080/docs/`. Without it the page is expected to 404 (reasoned from source, not run).
- Compose ports: backend 8080 (REST), UI 3000 (container port 80), Postgres 5433 on the host. The backend gRPC port 50051 is not published; the edge container reaches it over the compose network at `http://backend:50051`.
- The create admin page title is "Create Admin Account" and the submit button is "Create Admin" (`feature-toggle-ui/src/pages/CreateAdmin.tsx`). The login title is "Sign in to FluxGate" with submit "Sign in" (`Login.tsx`).
- Edge credentials for video 08: the edge needs `EDGE_CLIENT_ID` and `EDGE_CLIENT_SECRET` (`feature-toggle/feature-edge-server/CONFIG.md:11`; startup fails with `Failed to load configuration` if missing). These are a regular client's id (UUID) and API key: the edge sends them to the backend gRPC service, which looks up the client by UUID and checks its secret (`feature-toggle-backend/src/grpc/mod.rs` `verify_client_status`, around line 1107; edge side `feature-edge-server/src/grpc_client.rs:63-76`). So in video 08 create a client on the "Clients" page (`ClientCreate.tsx` shows the "API Key"), then export both variables and run `docker compose -f docker-compose.demo.yml --profile edge up -d`. The seeded id in `init.sql` is for test data only; do not use it. Do not use a System Client.
- Compose can take a minute on first pull; cut the wait in editing and keep the `docker compose ps` frame.
