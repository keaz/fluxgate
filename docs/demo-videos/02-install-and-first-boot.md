## Gotchas while recording

- Public distribution: the source repositories are private, so the viewer only has Docker Hub images and the two downloaded files. The compose file pins `keaz/flux-gate-backend:v1.2.0`, `keaz/flux-gate-ui:v1.2.0` and (edge profile) `keaz/flux-gate-edge:v1.2.0`; there is no build option. Never `cd` into a source checkout on camera; record from an empty folder holding only the two files. The website text that links the two downloads is a placeholder until the docs page exists.
- v1.2.0 contains the first-admin fix: right after "Create Admin" the next sign-in works on every backend worker, with no restart. Earlier images returned 401 from other workers until a restart. Verified live on 2026-10-05 with the published images: `POST /api/v1/admins` returned 201, then six `POST /api/v1/auth/login` calls and six `GET /api/v1/teams` calls with the new token all returned 200, and a second `POST /api/v1/admins` returned 403. `latest` and `v1.2.0` are the same build on Docker Hub (multi-arch amd64 and arm64); the compose file pins `v1.2.0`. Run `docker compose -f docker-compose.demo.yml pull` first and check that `docker compose -f docker-compose.demo.yml images` shows `v1.2.0`.
- Secrets typed or generated on screen are `<redacted>`: blur the value in the `cat .env` output (the `echo` line itself shows only the `$(openssl rand -base64 32)` expression), any `TYPESAFE_API_KEY` value, and the admin password fields. Never open `.env` on screen after video 08 adds the edge secret to it.
- Demo compose: `docs/demo-videos/assets/docker-compose.demo.yml` runs postgres, backend and ui; the `edge` service is behind profile `edge` and is started in video 08. It reads `FLUXGATE_ENCRYPTION_KEY` (required, compose refuses to start without it), optional `TYPESAFE_API_KEY`, `EDGE_CLIENT_ID` and `EDGE_CLIENT_SECRET` from the `.env` file in the folder you run compose from; docker compose loads that file automatically, and a variable exported in the shell overrides it. Keeping the values in `.env` means they survive a new terminal between videos. `EDGE_CLIENT_ID` and `EDGE_CLIENT_SECRET` default to empty: `docker compose config` failed on a plain `up -d` when they were marked required, because compose interpolates variables of services in inactive profiles too. The root `docker-compose.yml` of the product repository has no edge service and does not pass the encryption key, which is why the demo file exists.
- Encryption key lifetime: the backend encrypts stored Jira write-back tokens and SSO client secrets with `FLUXGATE_ENCRYPTION_KEY`. Write it once in video 02 and never regenerate it while the database lives; a new key makes those stored secrets unreadable. Run the `echo ... > .env` line only once (a second run overwrites `.env`).
- Data persistence: Postgres keeps its data in the named volume `pgdata`, so `docker compose -f docker-compose.demo.yml down` followed by `up -d` keeps every team, flag and user (checked live: sign-in worked after `down` and `up -d`). `down -v` deletes the volume and all FluxGate data; after that the UI asks for a first admin again. Use `down -v` only to reset the series.
- UI to backend address: the UI container has no proxy. The browser calls `${BACKEND_PROTOCOL}://${BACKEND_HOST}:${BACKEND_PORT}/api/v1` directly (`feature-toggle-ui/docker-entrypoint.sh:14-15`, also the WebSocket URL), so `BACKEND_HOST` in the compose file is `localhost`, the name the browser uses, and not the service name `backend`. Backend port 8080 is published to the host for that reason. If you record on a remote host, change `BACKEND_HOST` and `allowed_origin` in `config.demo.toml` together.
- Config path: the demo stack mounts `config.demo.toml` (same keys as the backend `config.toml`: `allowed_origin` set to `http://localhost:3000`, `http_addr`, `grpc_addr`, `public_base_url` commented out) from the folder the compose file is in.
- Deviation from the brief: the brief says `public_base_url` matters for the Jira Events URL. In the code the UI builds the Events URL from its own REST base URL (`feature-toggle-ui/src/utils/jiraIntegrations.ts:11-17`); `public_base_url` drives SSO callbacks (see `config.toml` comments). The voiceover therefore says Jira needs a public address to reach the backend, not that `public_base_url` sets the Events URL.
- Swagger path: the route is `/docs/{_:.*}` (`feature-toggle-backend/src/rest/mod.rs:769`) and the Swagger crate adds no redirect, so type the trailing slash: `http://localhost:8080/docs/`. Checked live on v1.2.0: `/docs/` returns 200 with the Swagger UI page, `/docs` returns 404.
- Compose ports: backend 8080 (REST), UI 3000 (container port 80), Postgres 5433 on the host. The backend gRPC port 50051 is not published; the edge container reaches it over the compose network at `http://backend:50051`.
- The create admin page title is "Create Admin Account" and the submit button is "Create Admin" (`feature-toggle-ui/src/pages/CreateAdmin.tsx`). The login title is "Sign in to FluxGate" with submit "Sign in" (`Login.tsx`).
- Edge credentials for video 08: the edge needs `EDGE_CLIENT_ID` and `EDGE_CLIENT_SECRET`. These are a regular client's id (UUID) and API key: the edge sends them to the backend gRPC service, which looks up the client by UUID and checks its secret (`feature-toggle-backend/src/grpc/mod.rs` `verify_client_status`, around line 1107; edge side `feature-edge-server/src/grpc_client.rs:63-76`). With the empty defaults the edge container still starts, but it is not usable: it logs `Failed to resolve the configured client's team: code=InvalidArgument msg=client_id is required` once a second and `/health` answers 503 `UNAVAILABLE` (`feature-edge-server/src/handlers.rs:971-974`; checked live on v1.2.0). So in video 08 create a client on the "Clients" page (`ClientCreate.tsx` shows the "API Key"), append both values to `.env`, and run `docker compose -f docker-compose.demo.yml --profile edge up -d edge`. The seeded id in `init.sql` is for test data only; do not use it. Do not use a System Client.
- Compose can take a minute on first pull; cut the wait in editing and keep the `docker compose ps` frame.
