## Gotchas while recording

- Account: `admin`, per the controller ruling that 04 is platform setup. Creating environments and pipelines has no role check (only `PATCH` needs an admin or `Team Admin`, `feature-toggle-backend/src/logic/policy.rs:379-399`), but the "Approval Policies" item under "Govern" is gated to `teamsManagement`, meaning an admin or `Team Admin` (`feature-toggle-ui/src/layout/navConfig.ts:99-106`). `admin` passes. Video 03 ends with `priya` signed in, so the first scene logs out and signs in as `admin`. If the team selector looks stale after switching users, reload the page.
- Approval policy dialog (`modals/ApprovalPolicyFormModal.tsx`): title "Create Approval Policy" (`:252`), fields "Policy Name" (`:264`), "Scope" with option "All Environments" (`:289,296`), "Approver Roles" (`:342`), submit "Create Policy" (`:461`). The page button is also "Create Policy" (`pages/ApprovalPoliciesPage.tsx:100`). "Required Approvals" (`:326`) keeps its default; leave the other fields alone. The role options come from the roles list, so `Approver` must exist (it does after video 03). Keep this segment short; video 10 covers approvals in full.
- Deviation from the brief: the dialog title and its submit button are both "Create Environment" (`modals/CreateEnvironmentModal.tsx:90,157`); "Create New Environment" is the button on the page (`pages/EnvironmentsPage.tsx:48`). The type choices are `Development`, `Staging` and `Production` (`CreateEnvironmentModal.tsx:122-124`). Environment names must be unique within a team (`feature-toggle-backend/src/rest/environment.rs:77`).
- Pipeline editor: there is no "Add Stage" button. A stage is added with a small unlabelled plus icon below a node (`components/PipelineNode.tsx:37-44`). The first node is labelled "Input Node" in code, but the node component never renders that label (`PipelineNode.tsx:15-45`). The environment selector's placeholder reads "Environment" (`PipelineNode.tsx:24`). The page labels are "Pipeline Name" and "Pipeline Stages" (`pages/PipelineCreate.tsx:256,271`). The submit button reads "Create Pipeline" and shows the toast "Pipeline created successfully" (`PipelineCreate.tsx:203,301`).
- Deviation from the brief: the brief says the pipeline gives "enforced promotion order". The code does not enforce that at deploy time. Nothing in the stage-change path checks that the parent stage is deployed first (`feature-toggle-backend/src/logic/feature.rs:1816-2000`, `src/validation.rs:51-81`). The pipeline fixes which environments a feature has and the order of its stages, so the voiceover claims only that.
- The pipeline list shows only "Name" and "Description" columns (`components/tables/PipelineTable.tsx:79,84`), not the stages. The environment list columns are "Environment ID", "Name", "Type" and "Status" (`components/tables/EnvironmentTable.tsx:95-111`).
- Environment dialog: after "Create Environment" the dialog keeps its last values. On the next open the "Environment Name" field still holds the previous name, selected, and "Environment Type" still shows the previous type. Typing replaces the name; change the type each time. The table sorts by name, not creation order, so it lists `Development`, `Production`, `Staging`.
- Pipeline editor trap (checked live on v1.2.0): the plus under the second stage adds the third stage to the right, outside the visible canvas at 1440x900, with no automatic fit-to-view. It looks as if nothing happened, and a second click adds a duplicate stage and edge. Saving then fails with the toast "Failed to Create Pipeline" and the description "Pipeline must have at least 2 relationships". Click the plus exactly once per stage, drag the canvas left to bring the new stage into view, and pick its environment there. If the toast appears anyway, reload `/pipelines/create` and start over. Saved result: stages at order 0, 1, 2 (`Development`, `Staging`, `Production`) with two relationships.
- Approval policy dialog defaults: "Scope" already reads "All Environments" and "Required Approvals" is 1 when the dialog opens, so only "Policy Name" and "Approver Roles" need input; the "Approver Roles" list is a multi-select, click `Approver` and then click the dialog heading to close the list. The new row in the table shows "Release approvals", scope "All Environments", 1 required approval, 1 role and the "Advisory" AI risk mode.
- Pipelines and environments are created for the team chosen in the header selector; with no team selected both forms show "Please select a team first." (`CreateEnvironmentModal.tsx:52-56`).
